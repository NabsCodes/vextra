# Site Phases

## Purpose

This document prevents the public teaser, social launch, and fuller studio site
from being mixed into one unclear release.

## Current Public Phase

The current website should present Vextra as an active software studio while
remaining honest that the fuller site is still being developed.

Approved public surface:

- Home
- selected work preview with three publishable systems
- project enquiry
- website launch list
- social channels
- Privacy baseline

Current message priorities:

1. what Vextra builds
2. evidence of shipped work
3. how to start a project
4. how to follow Vextra or receive the fuller-site announcement
5. quiet full-site progress status

The page should not read like a SaaS product launch or a company waiting to
begin operating.

## Current Launch Gates

Before publishing the current selected-work treatment:

- replace development placeholder artwork with approved UI captures or remove
  the affected visual
- confirm each client/project name is publishable
- remove private, personal, operational, or government-sensitive data from
  screenshots
- verify desktop and mobile crops
- verify Contact and launch-list delivery in the intended environment
- verify metadata and share cards on the deployed domain

Government and institutional client names require explicit publication
confidence. When a name cannot be published, use an accurate system type rather
than implying endorsement.

## Deferred Fuller-Site Scope

These are not part of the current teaser milestone:

- About and Team
- full Work index
- case-study pages
- Blog or Insights
- Academy
- CMS/editorial system
- photography program
- project metrics and filters
- inquiry management product or client portal

They should be introduced as approved slices, not scaffolded merely to make the
repository appear complete.

## Developing Future Pages

Future routes may be built locally or on isolated branches without changing the
current landing-page hierarchy.

Do not rely on an absent navigation link to hide deployed work. If an unfinished
route must exist in a preview deployment:

- use non-production or access-controlled preview infrastructure when possible
- otherwise apply `noindex`
- exclude it from the sitemap
- do not include confidential material

Public launch requires an explicit decision to add the route to navigation,
metadata, sitemap, QA, and ongoing content ownership.

## Full-Site Transition

When the fuller site is ready:

- replace the launch-list emphasis with the appropriate ongoing CTA
- remove or revise full-site progress language
- publish only approved project stories
- update navigation and sitemap together
- reconcile Home, footer, SEO, legal disclosures, and documentation in the same
  release slice

The launch list should not silently become a recurring marketing newsletter
without updated consent language and an approved delivery model.
